# クッキー型デザイナー 仕様書

作成: 2026-09-13 / 状態: 仕様検討（実装前）

---

## 1. 目的

クッキーの抜き型を、ブラウザ上で Inkscape のように点とベジェ曲線で設計し、
**抜き枠**と**スタンプ（蓋）**の2部品を STL として出力できるサイト。

### 想定利用者
地元の高校生。地域キャラクターをクッキーにして、イベントで販売する教育プログラムで使う。

### 2段階の運用（設計に影響する重要な前提）

| 段階 | 型の材質 | 必要な出力 |
|---|---|---|
| 第1段階: イベントでの一時販売 | PLA（3Dプリント）＋食品用フィルム介在 | 抜き枠STL・スタンプSTL |
| 第2段階: 菓子店での定期販売 | ステンレス（業者へ外注） | **輪郭の2Dデータ（SVG）** |

→ **同じデザインデータのまま第2段階へ移行できること**が設計要件。
詳細は `C:\Work\20_Notes\projects\cookie-cutter-designer.md` を参照。

## 2. 生成する部品

参考画像（犬の顔型、水色の枠＋ピンクのスタンプ）から確定した構造。

### 2.1 抜き枠（cutter）
- 閉じた輪郭に沿った薄壁のリング。底なし
- 下端は先細りの刃
- 上端にフランジ（ツバ）。指で押せる幅
- オプション: 第二の刃（extra blade）、中央支持バー（大型時）

**2部品に分ける判断の裏付け**: Tinkercad チュートリアルの著者が、一体型ではなく分離を勧めている。

> カッターとスタンプを一体化するより、切り抜いてから別途スタンプで模様を押す方が簡単。
> 生地を破らずに取り出すのが難しすぎるから

出典: https://www.instructables.com/Make-a-Cookie-Cutter-With-Tinkercad/

### 2.2 スタンプ（stamp / 蓋）
- 同じ輪郭の中実の板
- 板面にディテールが凸リブとして立つ。断面は丸みを持たせる
- 外周にも輪郭に沿った凸リブ（輪郭線自体も生地に転写される）
- 持ち手なしの平板を基本とし、任意で持ち手を付けられる

## 3. データモデル

### 3.1 中核となる分離: 輪郭レイヤー と ディテールレイヤー

これが仕様全体の背骨になる。

```ts
type Design = {
  version: 1
  name: string

  /** 輪郭。ただ1本の閉じたパス。抜き枠とスタンプ板の両方がここから生成される */
  outline: Path

  /** ディテール。本数自由。スタンプ面の凸リブになる */
  details: Detail[]

  /** 下絵（なぞる元にする画像） */
  underlay: Underlay | null

  params: Params
  grid: number
  snap: boolean
}

/** wire-frame-designer の Node2D をそのまま流用 */
type Node2D = { id: string; x: number; y: number; in: Vec2 | null; out: Vec2 | null }

type Path = { nodes: Node2D[]; closed: boolean }

type Detail =
  | { id: string; kind: 'stroke'; path: Path; width: number }   // 毛並みのような線
  | { id: string; kind: 'region'; path: Path }                  // 目・鼻のような塗り面

type Underlay = { dataUrl: string; x: number; y: number; scale: number; opacity: number; locked: boolean }
```

**なぜ分けるか**

1. 抜き枠は輪郭からのみ作る。ディテールは関係しない
2. ステンレスで作れるのは輪郭だけ。レイヤーが分かれていれば
   「輪郭は2Dデータで業者へ／ディテールは3Dプリントのスタンプに残す」が自然にできる
3. 検査ルールが両者で全く違う（輪郭は閉曲線・非自己交差が必須、ディテールは自由）

### 3.2 パラメータ

```ts
type Params = {
  /** 全体 */
  size: number              // 最長辺の寸法(mm)。これを基準に輪郭を拡縮

  /** 抜き枠 */
  wallHeight: number        // 壁の高さ
  wallThickness: number     // 壁の厚み
  bladeThickness: number    // 刃先の厚み
  bladeTaperHeight: number  // 刃先から壁厚に至るまでの高さ
  flangeWidth: number       // フランジの張り出し幅
  flangeHeight: number      // フランジの厚み

  /** スタンプ */
  plateThickness: number    // 板の厚み
  stampClearance: number    // 抜き枠の内側との隙間（片側）
  ribHeight: number         // 凸リブの高さ
  ribDraft: number          // 凸リブの抜き勾配(度)
  ribRound: number          // 凸リブ頂部の丸め半径
  outlineRib: boolean       // 外周リブを付けるか

  /** 検査のしきい値 */
  minDetailWidth: number    // これ未満のディテール線は警告
  minNeckWidth: number      // これ未満のくびれは警告
  minAngle: number          // これ未満の鋭角は警告
}
```

### 3.3 既定値

調査で得た実測値・実ツールの既定値に基づく。出典は `docs/RESEARCH.md`。

| パラメータ | 既定値 | 根拠 |
|---|---|---|
| size | 75 mm | Cookiecad の cutterSize 既定値 |
| wallHeight | 12.5 mm | Cookiecad の bladeDepth 既定値 |
| wallThickness | 1.2 mm | Cookiecad の Blade Thickness は0.8mm。**ノズル幅の整数倍必須**（後述）。生徒が扱うため強度側に倒す |
| bladeThickness | 0.4 mm | Cookiecad の Tip width 実値 |
| bladeTaperHeight | 2.0 mm | Cookiecad の Chamfer height 実値 |
| flangeWidth | 4.0 mm | Cookiecad の baseWidth 既定値 |
| flangeHeight | 3.5 mm | Cookiecad の baseHeight 既定値 |
| plateThickness | 3.0 mm | 平板の剛性確保 |
| **stampClearance** | **0.9 mm** | **Cookiecad の stampCutterTolerance。FDM一般則(0.2〜0.45mm)より大きい点に注意** |
| ribHeight | 1.5 mm | **Meshcast の「スタンプ詳細深さ」実値と一致**。Cookiecad は3mm |
| ribDraft | 5 度 | 金型一般則は1〜3°。生地離れ優先で大きめ |
| ribRound | 0.3 mm | 断面を丸めて生地離れを良くする |
| minDetailWidth | 1.2 mm | 細線は焼くと消える。一般則の「線幅2.5mm以上」より緩めだが要検証 |
| minNeckWidth | 3.0 mm | wallThickness×2 + 余裕 |
| minAngle | 20 度 | ステンレス曲げと刃の欠けの両方を考慮 |

**stampClearance = 0.9mm の理由**: 単なる嵌合公差ではなく、生地を挟んだ状態でスタンプが
引っかからずに動く必要があるため。通常のFDM公差の感覚で 0.3mm 等にすると失敗する。

### 3.4 壁厚はノズル幅の整数倍にスナップする（必須）

Cookiecad のフォーラムで報告された**「刃が割れる」不具合の原因は、
スライサーのライン幅（0.5mm）と刃厚（1mm）の不整合**だった。
半端な壁厚はスライサーが埋めきれず、層内に空隙ができて割れる。

出典: https://community.cookiecad.com/t/cutter-blade-splitting/767

```ts
nozzleWidth: number   // 既定 0.4mm。ユーザーが自分のプリンタに合わせる
```

- `wallThickness` は `nozzleWidth` の整数倍にスナップする（0.4mm なら 0.8 / 1.2 / 1.6 …）
- スナップ前の値も保持し、「1.2mm に調整しました」と画面に表示する
- **既存ツールにはない配慮。** 印刷失敗の実報告に直接対応する

### 3.5 ディテール線の一括太らせ

Cookiecad には `Imprint thickness`（既定 0mm）というパラメータがあり、
UI 上の説明は次のとおり。

> Make the imprint thicker or thinner. This is very useful for designs where
> the imprint lines are thin and need to be made thicker in order to be printable.

細線が印刷できない問題への実用的な対処。同等の機能を持たせる。

```ts
detailThicken: number   // 全ディテールのオフセット量。既定 0mm
```

検査（6.2）で細すぎる線が見つかったとき、この値を上げれば一括で解決できる。
**警告と、その場で直す手段をセットで提供する。**

│ ロゴ  [デザイン名]  ↶ ↷ │ 新規 │ JSON保存 読込 │ 書き出し ▾ │
├───────────────────────────┬─────────────────────────────┤
│ 2D 設計                    │ 3D プレビュー                │
│ ┌───────────────────────┐ │ ┌─────────────────────────┐ │
│ │ レイヤー: [輪郭][詳細] │ │ │                         │ │
│ │ ツール: 選択 ペン      │ │ │      (three.js)         │ │
│ │        ストローク 下絵 │ │ │                         │ │
│ ├───────────────────────┤ │ ├─────────────────────────┤ │
│ │                       │ │ │ 表示: 枠 / スタンプ /    │ │
│ │      SVGキャンバス     │ │ │       両方 / 重ねる       │ │

### 操作（wire-frame-designer の実装を流用）
- ノードをドラッグ: 移動
- ハンドルをドラッグ: 曲率変更
- 線をダブルクリック: 点を追加
- Del: 削除
- ホイール: 拡大縮小 / 背景ドラッグ: 表示移動
- ノードを選択後トグル: スムーズ ↔ コーナー
- グリッドスナップ

### レイヤー切替
- **輪郭モード**: 輪郭パスのみ編集可能。ディテールは薄く表示
- **詳細モード**: ディテールのみ編集可能。輪郭は薄く表示
- 誤って輪郭を壊すのを防ぐ。輪郭は1本しか存在できない制約をUIで担保

### 下絵
- 画像をドロップすると背景に表示。位置・拡大・不透明度を調整してロック
- その上をペンツールでなぞる
- **自動トレースは第3段階**。まず「なぞる」を提供する（実装が軽く、結果が確実）

## 5. ジオメトリ生成

### 5.1 基本方針

wire-frame-designer の方針をそのまま引き継ぐ。

> 書き出しと同じメッシュ生成を使い、画面で見た形がそのまま STL になる。

CSG は使わない。スライサーは重なったメッシュを問題なく結合するため、
「1個の閉じたソリッド」を目指す必要はない（wire-frame-designer で確認済みの判断）。

### 5.2 2つのプリミティブですべてを作る

**プリミティブA: プロファイルスイープ**

閉じた多角形と、断面プロファイル（オフセット量, 高さ）の列を与えると、
各プロファイル点で多角形をオフセットしてリングを作り、隣接リング間を三角形で繋ぐ。

```
sweepProfile(polygon: Vec2[], profile: {offset: number, z: number}[]) -> Mesh
```

抜き枠はこれ1つで表現できる。プロファイルは下から順に:

```
      offset →
     -0.3  0  +0.3          (bladeThickness=0.6 の例)
z=0    ├───┼───┤             刃先
          ↓ テーパー
z=3    ├─────┼─────┤         壁厚 1.2
          ↓ 直壁
z=12.5 ├─────┼─────┤
          ↓ フランジ
z=12.5 ├─────────┼─────────┤  フランジ幅 4.0（外側へ）
z=16   ├─────────┼─────────┤
```

外周リブ・凸リブもこれで作れる（ストロークを太らせ、上に行くほど細くすれば抜き勾配になる）。

**プリミティブB: 多角形の押し出し**

```
extrudePolygon(polygon: Vec2[], holes: Vec2[][], z0, z1, draft) -> Mesh
```

スタンプの板と、閉領域のディテールに使う。上下面の三角形分割が必要（凹多角形があるため）。

### 5.3 パイプライン

```
輪郭パス（ベジェ）
  │ sampleSegment で折れ線化（wire-frame-designer から流用）
  ↓
輪郭多角形
  ├─→ sweepProfile(輪郭, 抜き枠プロファイル) ────────→ 抜き枠メッシュ
  │
  └─→ offset(輪郭, -stampClearance)
        ├─→ extrudePolygon(..., 0, plateThickness) ──→ スタンプ板
        ├─→ sweepProfile(輪郭, 外周リブプロファイル) → 外周リブ
        └─ ディテール
             ├─ stroke → 太らせて多角形化 → sweepProfile → 凸リブ
             └─ region → offset → extrudePolygon(draft) → 凸リブ
```

### 5.4 ポリゴンオフセットについて

ここが技術的な核心であり、最大のリスク。

閉曲線を内外にオフセットすると、凹部では自己交差が発生する。素朴な実装では破綻する。
**自前で書かず、実績のあるライブラリを使う**（Clipper 系）。

- miter join（角を尖らせる）＋ miter limit で、鋭角部の暴走を抑える
- arc tolerance で曲線部の分割精度を制御

wire-frame-designer は依存を three だけに保っていたが、ここは例外として依存を足す価値がある。
オフセットの自前実装は、この規模のプロジェクトで最も時間を溶かす箇所。

## 6. 検査と警告

**既存ツールにない最大の差別化点。** Cookiecad 等は印刷して初めて問題が分かる。
ここでは設計中に警告を出す。

### 6.1 輪郭の検査（必須・エラー）

| 項目 | 判定 | 理由 |
|---|---|---|
| 閉じているか | 始点と終点が一致 | 抜き型として成立しない |
| 自己交差していないか | 線分交差判定 | オフセットが破綻する／ステンレス化不可 |
| 孤立した内部領域がないか | 輪郭は1本のみ | 1本の帯で表現できない |

### 6.2 印刷可能性の検査（警告）

| 項目 | 判定方法 | 既定しきい値 |
|---|---|---|
| くびれが細すぎる | **内側に r オフセットして領域が消滅/分断するか**で判定 | 3.0 mm |
| ディテール線が細すぎる | stroke の width | 1.2 mm |
| 鋭角すぎる | 隣接セグメントの角度 | 20 度 |
| 全体が大きすぎる | ビルドプレートに載るか | 200 mm |

**くびれ判定のテクニック**: 多角形を内側に r だけオフセットし、
領域が消える／2つに分かれる箇所があれば、そこの幅は 2r 未満。
オフセット処理をすでに持っているので追加コストがほぼない。

### 6.3 ステンレス化可否の検査（情報）

第2段階への移行可否を、設計中に示す。

| 項目 | 判定 |
|---|---|
| 1本の閉じた輪郭か | 6.1 と同じ |
| 鋭角が曲げられる範囲か | minAngle |
| 極端に小さい曲率半径がないか | 曲率計算。しきい値は業者確認後に確定 |

画面には「ステンレス化: 可 / 要調整」を常時表示する。
生徒がデザインした時点で第2段階の可否が分かるようにする。

## 8. 技術選定

| 項目 | 選択 | 理由 |
|---|---|---|
| ビルド | Vite + TypeScript | wire-frame-designer と同じ |
| フレームワーク | なし（Vanilla） | 同上。この規模では不要 |
| 3D | three | 同上 |
| ポリゴンオフセット | Clipper 系ライブラリ | 自前実装は破綻リスクが高い |
| 三角形分割 | earcut | 凹多角形の面張りに必要。軽量 |
| パッケージ管理 | pnpm | wire-frame-designer と同じ |
| 保存 | localStorage 自動保存 ＋ JSON 入出力 | 同上 |

### wire-frame-designer から流用するもの
- `Node2D` データモデル、ベジェ編集一式
  （`insertNode` / `deleteNode` / `setSmoothSegment` / `nearestOnPath` / `sampleSegment` / `snapValue`）
- バイナリSTL書き出し `stlBuffer`、`Mesh` 型
- `Preview3D` クラス
- JSON 検証、localStorage 自動保存、Undo/Redo、2ペインUIシェル、日本語UI

### 新規に書くもの
- ポリゴンオフセットのラッパ
- `sweepProfile` / `extrudePolygon`
- 輪郭とディテールの2レイヤー管理
- 検査ロジック
- 下絵表示
- SVG 出力

## 10. 未決事項

| 項目 | 内容 | 解決方法 |
|---|---|---|
| ステンレスの曲げ最小半径・鋭角限界 | 調査で確定値が得られず | 業者（馬嶋屋菓子道具店等）へ問い合わせ |
| ディテール凸部の最小幅 | クッキー専用の確立値なし。1.2mm は暫定 | 試作して実際に焼いて確認 |
| 抜き勾配の角度 | 金型一般則（1〜3°）のみ。5° は暫定 | 同上 |
| プランジャー機構 | 参考画像は持ち手なしの平板。ガイド/バネを付けるか | まず平板で試作し、使いにくければ検討 |
| フィルム越しの抜き味 | 細い形状はフィルム越しだと抜けない可能性 | 早い段階で実地テスト |

**暫定値はすべてパラメータとして露出し、試作結果で調整できるようにする。**
値を確定できないこと自体は問題ではない。調整できない設計にすることが問題。

## 11. 将来の拡張候補

### ローラーカッター
円柱状の型を転がして多数を一括で抜く方式。Meshcast が実装している
（ローラー直径60mm、長さ100mm、軸穴径8mm、周囲/縦のクッキー数 4×3）。

**イベントで数を作る用途に直接効く。** 輪郭データは同じものを使えるため、
第2段階以降の検討候補として有力。ただし輪郭が円筒面に巻かれるため、
歪みの補正が別途必要になる。

### 押しパッド（press handles）
Cookiecad にある、指で押すための別パッド。型本体とは別に、大きな面を重ねる。
既定値: 長さ50mm、幅60mm、角丸3mm、型との重なり7mm。

生徒が力を入れて押す用途では有効な可能性がある。フィルム越しに押すなら特に。

### その他
- テキストからの型生成（Cookiecad の弱点として指摘されている領域）
- 第二の刃（extra blade）による強度向上
- 大型時の中央支持バー
